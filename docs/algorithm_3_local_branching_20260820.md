# Algorithm 3 修订与初步试验（2026-08-20）

## 1. 定义与定位

本文将新方案记为 Algorithm 3（A3）：

> A3 = Algorithm 1 状态相关候选网络 + Algorithm 2 经济型构造解 + 自适应部分 local branching + 完整 reduced MIP 回退。

A1 和 A2 的定义保持不变。A3 不是替换 A1 的独立模型，而是在 A1 剪枝网络上增加一个有严格时间上限的邻域搜索阶段。

A2 仅设置 MIP Start，不改变可行域，也不缩小分支定界搜索树。A3 的目的则是在困难窗口中短暂限制离散车辆方案的搜索区域，先获得质量较好的 incumbent，再删除邻域约束并求解完整 reduced MIP。

## 2. 部分整数邻域

A3 只对未来的三组整数车辆变量建立邻域：

- 人工车辆弧：x_manual；
- 自动驾驶干线车辆弧：y_auto；
- 跨城直送车辆弧：w_direct。

连续货流变量不进入邻域，由 MIP 自由重新分配。

由于 A2 在硬时间上限下可能只构造部分方案，A3 不把“启发式中未出现的变量”解释为必须接近 0。设 S+ 为启发式明确给出正值的未来车辆变量集合，部分整数邻域为：

~~~
sum(|v_j - v_hat_j|, j in S+) <= k_eff
~~~

其中：

~~~
k_eff = min(
    local_branching_radius,
    max(1, ceil(0.25 * sum(v_hat_j, j in S+)))
)
~~~

未出现在 S+ 中的车辆弧保持自由，因此完整模型能够为已提交或在途货物补齐后续运输阶段。历史已提交变量不计入邻域半径。

默认参数为：

- local_branching_radius = 8；
- local_branching_time_fraction = 0.25；
- local_branching_max_time_sec = 2.0。

## 3. 自适应触发与时间分配

A3 沿用 A2 的困难窗口触发逻辑：

- 首个窗口不触发；
- 上一窗口完整 MIP 时间超过 heuristic_trigger_time_sec 时触发；
- 平均剩余窗口预算紧张，且上一窗口已消耗较高比例预算时触发；
- 容易窗口直接退化为 A1 reduced MIP。

触发后按以下顺序执行：

1. 复用 A1 候选网络；
2. 在不超过 1 秒的预算内构造 A2 部分解；
3. 在不超过 2 秒且不超过可用时间 25% 的预算内求解部分 local branching 模型；
4. 保存局部 incumbent；
5. 删除所有邻域辅助变量与约束；
6. 将局部 incumbent 写为完整模型的 MIP Start；
7. 用全部剩余时间求解不受邻域限制的 A1 reduced MIP。

至少为最终完整 MIP 预留 0.5 秒。局部阶段无解、超时或没有 incumbent 时，算法自动删除邻域并使用原 A2 部分 start（或无 start）进入完整 MIP。

## 4. 首版邻域被否决的原因

首版实现把所有未来车辆变量都纳入 L1 距离，启发式中未出现的变量中心为 0。在 1000 单、种子 6201 的试验中：

- t=4：局部模型状态 3，无 incumbent；
- t=6：局部模型状态 3，无 incumbent。

原因是 1 秒启发式只完成部分订单。大量未处理但必须为在途货物补齐的车辆弧被错误地限制在 0 附近，半径 8 不足以恢复完整可行路径。

因此，默认实现改为仅约束启发式非零支持集的“部分 local branching”。全变量邻域不再保留。

## 5. 修正版初步试验

实验复用 Algorithm 2 压力测试中的同一实例：

- 订单数：1000；
- 种子：6201；
- 城市对：Los Angeles–San Jose；
- 每个算法总时限：30 秒；
- H=8，rolling step=2，extension horizon=12；
- A1、A2、A3 使用相同订单和模型参数。

结果如下：

| 算法 | 总成本 | 最终 MIP Gap | 未服务率 | 总时间 |
|---|---:|---:|---:|---:|
| A1+MIP | 4498.7135 | 0.0007809 | 0.0054 | 30.25 s |
| A1+A2+MIP | 4502.6524 | 0.0013452 | 0.0024 | 30.27 s |
| A1+A2+A3+MIP | 4522.6524 | 0.0005346 | 0.0024 | 30.23 s |

修正版 A3 的局部阶段已经正常工作：

| 窗口 | 有效半径 | 局部状态 | incumbent 数 | 局部时间 | incumbent 转交 |
|---:|---:|---:|---:|---:|---|
| t=4 | 2 | 9（限时） | 5 | 2.034 s | 是 |
| t=6 | 2 | 9（限时） | 6 | 2.022 s | 是 |

## 6. 当前结论

这轮试验证明了 A3 的机制正确：

- 困难窗口会触发；
- 局部模型能够在预算内产生 incumbent；
- 邻域会在最终阶段前被删除；
- incumbent 能够成功转交给完整 reduced MIP；
- 最终 Gap 比本轮 A1 和 A2 都低。

但 A3 的滚动期总成本比 A2 高 20，比 A1 高约 23.94，因此不能据此宣称 A3 改善成本。t=4 窗口中，A3 与其他方法得到几乎相同的窗口目标，却选择了不同的近端车辆安排；这些等价或近等价决策被提交后改变后续车辆状态，最终产生更高滚动期成本。

这表明 A3 下一步的主要问题不是“如何找到局部 incumbent”，而是“如何在当前窗口近似同成本的方案中选择更有利于后续窗口的状态”。

## 7. 下一步建议

建议暂时把 A3 定位为实验性算法，并按以下顺序继续：

1. 为滚动窗口增加终端状态价值或二级目标，奖励下一窗口的车辆可用性与两城库存平衡；
2. 只在主目标差不超过容差时使用终端状态二级目标，避免牺牲当前窗口真实成本；
3. 记录 time-to-first-feasible 和 incumbent 轨迹，计算 primal integral；
4. 在 1000/2000 单上进行至少 30 个配对种子；
5. 分别对有效半径比例、最大半径和局部时间占比做消融。

在多种子结果完成前，A3 的合理表述是：

> An adaptive partial local-branching matheuristic that improves the search trajectory in difficult rolling-horizon windows, while retaining an unrestricted reduced-MIP fallback.

不应表述为保证降低成本或保证加速。

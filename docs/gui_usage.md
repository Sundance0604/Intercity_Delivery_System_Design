# 可视化仿真实验界面操作说明

本文档说明 `python main.py` 启动后的可视化界面、动态参数输入格式和推荐实验流程。

## 1. 启动

```bash
conda activate pavane
python main.py
```

不打开窗口时可使用命令行：

```bash
python main.py --cli --scenario quick --solver exact_mip
python main.py --cli --scenario sensitivity --solver exact_mip --seeds 3 --time-limit 500
python main.py --cli --scenario sensitivity --solver exact_mip --seeds 1 --dry-run
```

## 2. 实验场景

界面只保留两类场景：

| 场景 | 含义 |
|---|---|
| 快速测试 `quick` | 使用默认模型参数生成一个小算例，检查环境、模型和输出链路 |
| 灵敏度分析 `sensitivity` | 对全部模型参数和订单生成参数执行单因素灵敏度分析 |

订单规模本身是灵敏度参数 `input.num_orders`。通过设置它的水平，可以同时完成原来的
小规模基准和规模扩展实验，因此不再单独保留 `baseline` 与 `scale`。

## 3. 固定输入项

| 输入项 | 格式 | 含义 |
|---|---|---|
| 每个水平随机种子数 | 正整数，如 `3` | 每个参数水平重复生成的随机实例数 |
| 单算例时间限制(秒) | 正整数，如 `500` | 每次调用求解器的时间上限 |
| 快速测试订单数 | 正整数，如 `20` | 只影响 `quick` 场景 |

灵敏度算例数的计算方式为：

```text
算例数 = 所有参数的水平数之和 × 每个水平随机种子数
结果行数 = 算例数 × 已选求解器数
```

当前默认配置共有 14 个模型参数和 5 个订单参数，`seed_count=1` 时共生成 60 个
灵敏度算例。用户在 `config.py` 新增字段后，参数数目和算例数会自动增加。

## 4. 灵敏度水平输入格式

所有灵敏度水平统一使用 JSON 数组，避免字典、区间和普通列表之间产生歧义。

| 参数类型 | 正确示例 |
|---|---|
| 整数 | `[12,24,36]` |
| 小数 | `[7.5,15.0,22.5]` |
| 布尔值 | `[false,true]` |
| 区间 | `[[0,1],[0,5],[0,8]]` |
| 城市字典 | `[{"1":10,"2":10},{"1":30,"2":30}]` |

注意：

1. 必须保留最外层方括号。
2. JSON 布尔值写作小写 `true`、`false`。
3. 字典的城市键可写成字符串，程序会按 `config.py` 默认值自动恢复为整数键。
4. 每个输入框至少保留一个水平；只填一个水平时仍会生成该参数的一组实验。

## 5. 动态模型参数

界面中名称以“模型参数”开头的输入项来自 `DeliveryConfig`。当前包括：

| 参数 | 含义 | 默认水平生成方式 |
|---|---|---|
| `T` | 离散规划期长度 | 默认值的 0.5、1.0、1.5 倍 |
| `t_0` | 单个时间段长度 | 默认值的 0.5、1.0、1.5 倍 |
| `travel_time_periods` | 城际行驶时间段数 | 默认值的 0.5、1.0、1.5 倍 |
| `N_manual` | 两城市人工车辆数量 | 整个字典同步按比例缩放 |
| `N_auto` | 两城市自动驾驶车辆数量 | 整个字典同步按比例缩放 |
| `capacity_manual` | 人工车辆容量 | 默认值的 0.5、1.0、1.5 倍 |
| `capacity_auto` | 自动驾驶车辆容量 | 默认值的 0.5、1.0、1.5 倍 |
| `cost_manual` | 人工车辆单位成本 | 默认值的 0.5、1.0、1.5 倍 |
| `cost_auto` | 自动驾驶车辆单位成本 | 默认值的 0.5、1.0、1.5 倍 |
| `penalty_lost` | 单位未服务惩罚 | 默认值的 0.5、1.0、1.5 倍 |
| `service_a_1`、`service_b_1` | 城市 1 服务效率参数 | 默认值的 0.5、1.0、1.5 倍 |
| `service_a_2`、`service_b_2` | 城市 2 服务效率参数 | 默认值的 0.5、1.0、1.5 倍 |

默认水平只是便于试跑的起点，不代表论文中的最终取值。应结合参数单位、现实数据和
模型可行性调整。例如修改 `T` 时，需要同时确认它大于城际行驶时间和时间窗长度。

### 新增 config 参数

`DeliveryConfig` 必须继续使用 dataclass。新增带默认值的字段即可：

```python
@dataclass
class DeliveryConfig:
    # 现有字段……
    carbon_cost: float = 2.0
```

重新启动 GUI 后会自动出现“模型参数 carbon_cost”。该字段会同时进入：

1. 灵敏度参数输入区；
2. 单因素算例生成；
3. CSV 的 `Config_carbon_cost` 列；
4. JSON 的 `config.carbon_cost` 字段。

不需要修改 `experiment_gui.py`。但底层模型若要实际使用新参数，仍需在相应模型代码
中引用该字段。

## 6. 动态订单参数

| 参数 | 含义 | 默认水平 |
|---|---|---|
| `input.num_orders` | 订单批次数，即实验规模 | `[20,50,100,200]` |
| `input.buffer_range` | 时间窗随机缓冲上下限 | `[[0,1],[0,3],[0,5],[0,8]]` |
| `input.large_order_prob` | 大订单出现概率 | `[0.1,0.3,0.5,0.7]` |
| `input.small_quantity_range` | 小订单货量上下限 | `[[5,25],[10,50],[20,100]]` |
| `input.large_quantity_range` | 大订单货量上下限 | `[[50,150],[100,300],[200,500]]` |

`input.num_orders` 可同时承担小规模最优解测试和规模扩展测试。建议按求解能力设置为
`[20,50,100,200,500]`，并根据大规模实例的求解时间决定是否加入 `1000`。

## 7. 单因素实验含义

程序使用 OFAT（One Factor At A Time）方式。测试某个参数时：

1. 被测试参数取输入框中列出的各个水平；
2. 其余 `DeliveryConfig` 参数保持 `config.py` 默认值；
3. 其余订单参数保持 `experiment_core.py` 的基础值；
4. 每个水平使用相同的一组种子编号 `3001、3002……`。

同一 seed 下改变模型参数时，随机数序列一致；改变会直接影响订单生成机制的参数时，
订单内容会按该参数重新生成。输出中的 `Sensitivity_Parameter` 和
`Sensitivity_Value` 明确记录本行实际变化的因素。

## 8. 推荐运行流程

1. 只勾选 `quick`，确认 Gurobi、模型和文件输出正常。
2. 勾选 `sensitivity`，设置随机种子数为 `1`，刷新预览并检查算例数。
3. 先缩短时间限制试跑，排除不合理水平，例如规划期过短或区间上下限错误。
4. 正式实验将种子数增加到 `3`、`5` 或 `10`。
5. 实现新算法后同时勾选两个求解器，按相同 `Exp_ID` 比较结果。

## 9. 常见错误

| 提示或现象 | 原因与处理 |
|---|---|
| “请输入合法的 JSON 数组” | 检查方括号、英文逗号、双引号和 JSON 布尔值 |
| “参数水平必须包含 2 个元素” | 区间必须写成 `[下限,上限]` |
| 全部需求未服务 | 检查惩罚成本、车辆成本、运力和时间窗是否量纲失衡 |
| Rolling Horizon 无有效解 | 当前只是接口占位，尚未实现算法 |
| 算例数过多 | 先减少 seed 数或每个参数的水平数 |
